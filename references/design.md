# 設計與限制

## 原瀏覽器優先

技能沿用平台內建 browser use 工具與原分頁。腳本用於讀取或宿主明確允許的操作，登入、驗證、風控與最後下單由使用者接手。不安裝瀏覽器套件、不自行啟動瀏覽器、不複製 cookies、不另接 CDP。

蝦皮[官方帳號說明](https://help.shopee.tw/portal/4/article/79734)列有機器人使用或登入的凍結風險。原瀏覽器與降低操作頻率也不能保證通行。不得為取得通行而連續重試或切換帳號、IP 或其他通路。

## 分工

- 宿主負責實際瀏覽器、正式操作工具、可見頁面證據、接手介面與使用者授權。
- 技能負責購物流程、商品核對、停止條件、最後下單前交接。
- Node.js CLI 負責產生操作、保存節流及狀態、操作識別與加入防重送；不直接控制瀏覽器。
- 頁面腳本只讀取必要商品資料，或在允許的讀寫模式中執行有核對條件的操作。

```text
綁定原分頁 → 登入檢查 → 搜尋 → 商品核對 → 規格與數量 → 加入一次 → 購物車 → 結帳交接
                    ↘ 登入 / 驗證 / 風控 / 結果不明 → 使用者接手 → 原分頁恢復
每一步：plan → 宿主執行一次 → 觀察 → record
加入：先記錄已發出意圖 → 送出一次 → 只觀察成功提示 → 不明就人工核對
```

狀態保存在 `.local/state.json`，同一目錄以原子建立 `lock` 目錄排他，寫入採暫存檔及重新命名。這不能鎖住其他目錄或工具直接操作同一瀏覽器，宿主仍須確保單一操作來源。

加入意圖依商品網址、標題、排序後的規格與數量計算 SHA-256；一旦產生操作就視為可能已送出，除非使用者明確確認沒有加入，否則不能再送。同樣的成功意圖不可重送；要改數量時由使用者修改購物車。這是本機防重複，不是蝦皮伺服器冪等保證。

腳本的驗證偵測只能涵蓋部分網址、可見 CAPTCHA、簡訊欄位及明確阻擋文字。HTTP 證據須由宿主工具提供；沒有能力時依實際頁面判斷，不能宣稱有全面網路攔截。

## 未完成範圍

尚未完整實站校準商品與購物車 selector，也未驗證每個平台端到端流程。價格、評分、運費保留可見文字，尚未做完整正規化、跨頁搜尋、優惠最佳化、所有規格群組適配、自動勾選購物車、配送與付款填寫。CLI 不會自主操作宿主工具，須由載入技能的代理執行操作與回報。

結帳腳本只在購物車點擊明確的「去買單／結帳」，立即交接；實際是否已抵達結帳頁由宿主觀察，不能僅根據 click 回傳就宣稱完成。最後送出與付款沒有命令。

## 驗證層級

本機測試驗證狀態與腳本條件，不開瀏覽器、不使用帳號或建立訂單。2026-10-15 已在原 Codex 瀏覽器讀取蝦皮首頁及登入連結，確認唯讀腳本可用；沒有登入、加入或結帳的實站成功證據。

後續實站驗收：

1. 在宿主原分頁確認接手與恢復方式，校準登入標記；由使用者登入。
2. 搜尋一次，核對搜尋結果與商品資訊，確認操作仍是原分頁。
3. 使用者選定並授權加入一件，校準規格、數量、加入及成功提示，人工核對購物車。
4. 使用者勾選本次商品後進入結帳，觀察實際頁面並交接。測試不要求購買。
5. 遇到阻擋立即停止，不刻意觸發風控來測試。紀錄版本、日期與結果，不保存個資、cookies 或完整截圖。
